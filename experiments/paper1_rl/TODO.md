- [x] **Found the actual bug**: `ValueBaseline` was instantiated and added to the optimizer but never called anywhere — its parameters got zero gradient forever, so training was pure high-variance REINFORCE with only a crude per-episode return z-score, no real state-dependent baseline. That's a textbook setup for policy collapse over many updates. Fixed: `baseline(l_obs)` is now called every step, advantage = return − baseline (normalized), the baseline is trained with an MSE loss, a small entropy bonus (`entropy_coef=0.02`) discourages premature collapse, and gradients are clipped (`max_norm=5.0`).

- [x] **Root cause was not undertraining — it was a learning-rate instability.** Ran a single-bandwidth (B=8) diagnostic to 4000 episodes at the default `lr=3e-3`: training returns don't converge, they *diverge* over the long run (mean return -55 at ep 400 → -157 at ep 4000). Dropping to `lr=5e-4` stabilizes training completely (flat around -40 to -45 for the full 4000 episodes). "Train longer" was the wrong lever; the previous 3000-episode "it got worse" result was this same instability, not a fluke. `--lr` is now a CLI flag on `run_bandwidth_sweep.py`.
- [x] **Widened the bandwidth grid to {1,2,4,8,16,32,64,128} at the stable `lr=5e-4` — and found a second, bigger problem: the TE estimator itself is biased.** At B=128 with only 20 eval episodes (~500 samples), `cl.predictive_gain_te` reported *rising* TE that never plateaued (0.01 → 1.96 bits, accelerating increments) even though eval task returns were flat across all bandwidths (task performance not improving with more bits — a red flag that the channel wasn't being used for anything real). Control test nailed it: feeding the estimator **pure random noise** (independent message vs. independent state, true TE = 0) at n_bits=128, n_samples=500 reports **0.71 bits of fake coupling**, growing with n_bits. `predictive_gain_te` is an in-sample linear-regression estimator (`_ridge_residual_cov`, ridge=1e-6); as feature dimension (n_bits) approaches the eval sample count, in-sample R² is mechanically inflated even for pure noise — classic finite-sample/dimensionality bias. Stage 1's `T=6000` samples vs. `B≤32` was never in this regime (187:1 ratio); Stage 2's 20-episode eval set (~500 samples) vs. `B` up to 128 (~4:1) was squarely in it.
